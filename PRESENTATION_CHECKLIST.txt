Пройдите список сверху вниз. Пункты со звёздочкой (*) обязательны для

---------------------------------------------------------------------------
1. БЕЗОПАСНОСТЬ (secrets\.env.local) — ОБЯЗАТЕЛЬНО
---------------------------------------------------------------------------
* JWT_SECRET       — заменить "change-me-in-production" на длинную случайную
                     строку (иначе токены входа можно подделать).
* ADMIN_PASSWORD   — заменить дефолтный "admin123" на свой пароль.
* ADMIN_EMAIL      — поставить рабочий e-mail администратора.
* POSTGRES_PASSWORD— задать надёжный пароль БД (и синхронно в DATABASE_URL).
* CORS_ORIGINS     — указать реальный домен сайта, убрать localhost:5500.

  Проверить, что дефолты не остались, можно в админ-панели → «Диагностика»:
  строки «JWT-секрет по умолчанию» и «Пароль админа по умолчанию» должны
  быть «нет» (не красные).

---------------------------------------------------------------------------
2. РЕЖИМ ПОКАЗА (DEMO_MODE в secrets\.env.local)
---------------------------------------------------------------------------
- DEMO_MODE=1 — «инсайдерский» показ: каталожные данные (цены/характеристики)
  скрыты серой плашкой «Недоступно в инсайдерской версии». Ставьте, если
  показываете интерфейс людям, которым нельзя видеть реальные данные.
- DEMO_MODE=0 (или строки нет) — всё видно. Ставьте для реальной работы.

---------------------------------------------------------------------------
3. РАЗДЕЛЫ, НАМЕРЕННО ЗАКРЫТЫЕ («в разработке»)
---------------------------------------------------------------------------
- Вкладка «Доставка» залита серым с красной надписью ВСЕГДА (заглушка).
  Открыть, когда раздел будет готов: убрать атрибут data-locked-section
  у блока <div class="row g-4" ...> в frontend/delivery.html.
- Вкладка «Проект для клиента» («Мой проект») сейчас оформлена как
  клиентская спецификация. Если нужен отдельный кабинет сотрудника —
  это отдельная доработка (см. TROUBLESHOOTING.txt / раздел «Проект»).

---------------------------------------------------------------------------
4. КАРТИНКИ И БРЕНДИНГ (папка photos\)
---------------------------------------------------------------------------
- logo.png             — логотип в шапке сайта.
- ВЕНТМАШ_ЛОГО.png     — водяной знак PDF по умолчанию (кладите сюда; он сам
                         выберется в окне «Просмотр PDF»).
- ШАПКА_ЛОГО.png       — логотип для фирменной шапки (бланка) в PDF. Сама
                         шапка «модульная»: реквизиты и кликабельная ссылка
                         на сайт рисуются текстом — править их в
                         backend\presentation\app.py (константы LETTERHEAD_*).
- Фото по типам        — vo.jpeg / vc.jpeg / vr.jpeg / vkop.jpeg / uvo.jpeg /
                         c.jpeg (показываются в каталоге и карточке).
- Чертежи:
    blueprint.png        — общий чертёж (или blueprint_<слаг-модели>.png);
    blueprintVals.png    — таблица значений (или blueprintVals_<слаг>.png).
  Пока файлов нет — на карточке и в PDF показываются SVG-заглушки «синьки».
- Иконки сайта (favicon): положить квадратный логотип в
  photos\favicon_template.png и выполнить:
      pip install pillow
      python scripts\generate_favicons.py

---------------------------------------------------------------------------
5. ДАННЫЕ КАТАЛОГА
---------------------------------------------------------------------------
- Актуальный CSV: data\ventsearch_massive_sorted.csv (формат имён
  «ВО 13-284-4/15°-4-56A4», типоразмер = маркировка двигателя, напр. 56A4).
- Резервные/тестовые CSV в data\old\ на сервер не нужны — можно удалить.
- После правки CSV сервер сам перечитает его (по mtime/размеру); при
  необходимости — админ-панель → «Диагностика» → «Перечитать CSV сейчас».

6. АНАЛИТИКА / ВНЕШНИЕ СЧЁТЧИКИ
---------------------------------------------------------------------------
- На всех страницах вставлен счётчик Яндекс.Метрики (id 109006784).
  Если презентация не должна слать данные наружу — временно удалите блок
  <!-- Yandex.Metrika counter --> ... <!-- /Yandex.Metrika counter -->
  из frontend\*.html (или замените id на свой).

---------------------------------------------------------------------------
7. ЗАПУСК
---------------------------------------------------------------------------
- База данных (Postgres) поднимается в Docker:
      docker compose -f deploy\docker-compose.dev.yml up -d
- Сайт (backend + фронт) — БЕЗ Docker:
      deploy\run.bat
- Открывать в браузере ТОЛЬКО:  http://127.0.0.1:8000/
  (uvicorn пишет «0.0.0.0:8000» — это не адрес для браузера, а «все
  сетевые адреса»; см. TROUBLESHOOTING.txt).
- Для реального сервера: запускать за обратным прокси (nginx) с HTTPS,
  а не отдавать uvicorn напрямую в интернет.
