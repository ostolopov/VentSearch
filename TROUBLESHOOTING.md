# Запуск и типовые проблемы (шпаргалка)

Короткая справка по командам и ошибкам, с которыми реально сталкивались при
локальном запуске на Windows. Для первого знакомства с проектом — см.
[docs/INSTALL_LOCAL.md](docs/INSTALL_LOCAL.md). Этот файл — «скорая помощь»,
когда что-то уже не работает.

## Как всё устроено

- **PostgreSQL** запускается в Docker: `deploy/docker-compose.dev.yml`.
- **Backend** (FastAPI) запускается НЕ в Docker — обычным Python-процессом
  через `run.bat`. Docker отвечает только за базу данных.
- **Frontend** — статические файлы, которые раздаёт сам backend
  (`http://localhost:8000`).

Из этого следует важное: если сломалось что-то в самом сайте (не в базе) —
перезапуск Docker чаще всего ничего не даст, потому что backend и frontend
в Docker вообще не живут.

## Команды на каждый день

```bat
:: поднять базу данных (один раз после перезагрузки компьютера)
docker compose -f deploy\docker-compose.dev.yml up -d

:: проверить, что база жива
docker compose -f deploy\docker-compose.dev.yml ps

:: запустить сайт
run.bat

:: проверить, что backend отвечает
curl http://localhost:8000/api/health
```

Ожидаемый ответ `/api/health`: `{"ok":true,"products":ЧИСЛО,"demo_mode":false}`.

## Частые ошибки

### 1. `Connection refused` на порту 5432

Postgres не запущен. `run.bat` его не поднимает — это делает только
`docker-compose.dev.yml`. Решение:

```bat
docker compose -f deploy\docker-compose.dev.yml up -d
```

### 2. Сайт не пускает / странные ошибки после правки `secrets\.env.local`

Проверьте, что `DATABASE_URL` и `POSTGRES_USER` / `POSTGRES_PASSWORD` /
`POSTGRES_DB` **согласованы** — это одна и та же база, названная дважды.
Если один блок правили, а другой нет, backend будет пытаться подключиться
не туда:

```
POSTGRES_USER=ventmash
POSTGRES_PASSWORD=ventpass
POSTGRES_DB=ventmash
DATABASE_URL=postgresql://ventmash:ventpass@localhost:5432/ventmash
```

Логин и пароль в `DATABASE_URL` должны буквально совпадать с `POSTGRES_USER`
/ `POSTGRES_PASSWORD` выше.

### 3. Ошибки то есть, то нет; `/api/products/facets` 500; не получается войти — хотя всё вроде запущено

Почти всегда это **не новая поломка**, а старый процесс backend, который
не завершился при предыдущей остановке и продолжает висеть на порту 8000
рядом с новым. Браузер стучится то в старый (сломанный) процесс, то в
новый — отсюда непредсказуемость.

Проверить, кто сидит на порту:

```bat
netstat -ano | findstr :8000
```

Если строк больше одной (кроме `TIME_WAIT`) — это и есть проблема. Завершить
процесс по PID:

```bat
taskkill /F /PID <тот_самый_PID>
```

### 4. `taskkill` пишет «не может найти процесс», а `netstat` всё равно показывает порт занятым

Это не баг сайта — это осиротевший сокет от сетевого слоя Docker Desktop
(WSL2), который держит порт, но уже не привязан ни к одному живому
Windows-процессу. Обычный `taskkill` его не видит. Решение по нарастающей:

```bat
wsl --shutdown
```

затем перезапустить Docker Desktop. Если не помогло — перезагрузка
компьютера гарантированно освобождает порт.

### 5. Заменили файл (фото, favicon), а на сайте всё равно старая версия

Это не Docker и не backend — файл на диске уже новый, backend отдаёт его
сразу. Дело в **кэше браузера**: URL картинки не меняется при замене файла,
и браузер показывает то, что закэшировал раньше. Решение:

- жёсткое обновление страницы (`Ctrl+Shift+R`) или окно инкогнито;
- для `photos/*.jpg|png` кэш сбивается автоматически (добавляется
  `?v=<время изменения файла>`) — если после правки фото всё равно старое,
  проверьте вкладку Network в DevTools: грузится ли новый `?v=...`;
- у favicon.ico браузеры кэшируют иконку особенно агрессивно и надолго —
  иногда помогает только очистка данных сайта в настройках браузера;
- важно: раньше сервер вообще не отдавал favicon-файлы (белый список
  статики их не включал, всегда был 404) — если иконки нет, убедитесь,
  что backend обновлён, и проверьте `curl http://localhost:8000/favicon.ico`
  (должен быть ответ 200, а не 404).

### 6. Не появляется серая плашка «Недоступно в инсайдерской версии»

Проверьте `secrets\.env.local` — там должна быть строка `DEMO_MODE=1` (без
неё режим выключен, и все данные видны как обычно — это нормальное
поведение, не баг). Если строка есть и всё равно не работает — см. пункт 5
(кэш браузера) и пункт 3 (лишний процесс backend).

## Свои иконки сайта (favicon)

Иконки генерируются из одного файла-шаблона скриптом, а не редактируются
руками по отдельности:

```bash
pip install pillow
python scripts/generate_favicons.py
```

Положите свой логотип (квадратный, от 512×512, лучше PNG с прозрачным
фоном) в `photos/favicon_template.png` и запустите скрипт — он пересоздаст
`favicon.ico`, `favicon-16x16.png`, `favicon-32x32.png`,
`apple-touch-icon.png` в `frontend/`.

## Водяной знак и заголовок в PDF («Документ для клиента»)

Кнопки «Документ для клиента (PDF)» / «PDF для клиента» есть на странице
сравнения, на карточке модели и в «Моём проекте» — все они открывают одно
и то же окно: своё название шапки документа (если оставить пустым —
остаётся текст по умолчанию), водяной знак, предпросмотр и скачивание.
Водяной знак — любой файл-картинка из папки `photos/`. Чтобы добавить свой
вариант, просто положите файл (`.png`/`.jpg`/`.webp`/`.gif`) в `photos/` —
он сам появится в выпадающем списке.

## Чертежи из каталога на карточке модели

Блок «Чертёж из каталога» на странице модели показывает файл
`photos/blueprint_<слаг-модели>.png` (также подойдут `.jpg`/`.jpeg`/`.webp`).
Точное ожидаемое имя файла для конкретной модели написано в подсказке прямо
под блоком — скопируйте его, положите скан из бумажного каталога с этим
именем в `photos/`, и он появится сам (без перезапуска). Пока файла нет,
показывается шаблон-заглушка `frontend/img/blueprint-placeholder.svg`.

## Сортировка каталога

Каталог — таблица: клик по заголовку колонки (Расход, Давление, Мощность,
Шум, Цена, Диаметр, Модель) сортирует весь каталог по этой колонке,
повторный клик — в обратную сторону. Сортируется на сервере, поэтому
порядок честный по всем страницам, а не только по видимой.
